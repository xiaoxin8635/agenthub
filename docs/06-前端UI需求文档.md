# 06 前端 UI 需求文档：AgentHub Console

> AgentHub 的 Web 控制台需求基线。目标：让「上传资产 → 生产数据集 → 发起评测 → 查看结果 → 回灌 badcase」的完整闭环**全程在浏览器中完成，无需命令行**。功能需求见 [00-需求文档](./00-需求文档.md)，本文档只覆盖 UI 层。

## 1. 设计目标与原则

| 原则 | 落地方式 |
|---|---|
| 操作路径最短 | 核心闭环任一步骤 ≤ 3 次点击可达；每步完成后提供「下一步」引导（导入完→去建集，发布完→去评测） |
| 列表轻、详情重 | 列表页 = 筛选器 + 表格；详情页 = 多 Tab 承载深度信息；所有实体详情用**侧滑抽屉**（不打断列表上下文） |
| 数据可读性优先 | 通过率/分数用语义色（绿/黄/红）+ 进度条；失败项一键筛选；对比用差异高亮（涨绿跌红） |
| 中文优先 | 全站中文；专业术语首次出现给英文标注（如「指标组合 MetricConfig」） |
| 危险操作防护 | 删除数据集/资产二次确认并输入名称确认；发布版本显示 diff 预览后才可确认 |

## 2. 借鉴分析

| 参考对象 | 借鉴点 |
|---|---|
| Langfuse | 左侧固定导航 + Trace/数据集/Dataset Run 的信息架构；Run 详情「概览卡 + 逐条表格 + 失败筛选」三段式 |
| promptfoo | 逐 case 结果表格（输入/输出/逐指标打分并列）；断言（指标）级别的红绿点阵 |
| 阿里云数据中台 / Quick BI | 仪表盘「指标卡 + 趋势图 + 排行榜」组合；筛选器置顶、面包屑导航 |
| Ant Design Pro / Databricks | Pro 版表格（列设置、密度切换、列排序）、抽屉表单、步骤条向导 |

## 3. 信息架构（站点地图）

```
AgentHub Console
├── 仪表盘 Dashboard
├── 数据资产
│   ├── 资产列表（含导入入口）
│   └── 资产详情（抽屉）
├── 评测数据集
│   ├── 数据集列表（含创建入口）
│   └── 数据集详情
│       ├── Tab1 数据管理（草稿/已发布 item 表格 + 圈选资产向导）
│       ├── Tab2 版本与快照（版本时间线 + 快照预览 + 导出下载）
│       └── Tab3 badcase 回灌记录
├── 评测中心
│   ├── 评测任务列表（Run 列表，含发起入口）
│   ├── 发起评测（向导：选版本 → 选 Target → 选指标组合 → 确认）
│   ├── Run 详情
│   │   ├── 概览（summary 指标卡 + 指标雷达/条形图）
│   │   ├── 逐 case 结果（表格：输入/输出/逐指标分数/passed，失败筛选）
│   │   └── 版本对比（选另一 Run → 指标差值 + 回归/修复 case 清单）
│   └── 被测目标与指标组合（Target / MetricConfig 管理 + 指标目录）
└── 设置（API Key、LLM Judge 配置状态、数据目录）
```

导航形态：左侧固定侧边栏（可折叠，宽 220px），顶部面包屑 + 全局搜索（资产/数据集/Run 三类实体）。

## 4. 页面功能需求

### 4.1 仪表盘（UI-100）

| 编号 | 需求 |
|---|---|
| UI-101 | 顶部指标卡 4 张：资产总数、数据集数（含版本总数）、评测 Run 数、近 30 天平均通过率（环形进度） |
| UI-102 | 通过率趋势折线图：按天聚合所有 Run 的 pass_rate（近 30 天），hover 显示当日 Run 数 |
| UI-103 | 最近评测 Run 列表（前 10）：数据集@版本、Target、agent_version、通过率条、状态、时间，点击进 Run 详情 |
| UI-104 | 待办提示条：有草稿未发布的数据集 N 个 / 有失败 case 未回灌的 Run N 个，点击直达对应页面 |
| UI-105 | 全部空状态给「快速开始」三步引导（上传资产 → 创建数据集 → 发起首次评测） |

### 4.2 数据资产（UI-200）

| 编号 | 需求 |
|---|---|
| UI-201 | 列表：Pro 表格（列：类型徽标、来源徽标、内容摘要（截断+悬浮全文）、标签（多彩 tag）、创建时间、操作）；筛选器置顶（类型/来源/标签/关键词，防抖 300ms）；分页 20/页 |
| UI-202 | 导入向导：对话框三步——①选择文件（拖拽 JSONL）②选 source + 输入 tags ③导入结果（created/skipped/errors 逐行展示） |
| UI-203 | 资产详情抽屉：content 结构化展示（JSON 树）、标签编辑（就地增删）、来源/哈希/时间元信息、删除（输入名称确认） |
| UI-204 | 圈选联动：列表勾选 N 条 → 批量栏浮出「加入数据集…」→ 选目标数据集 → 调 from-assets（asset_ids 模式） |

### 4.3 评测数据集（UI-300）

| 编号 | 需求 |
|---|---|
| UI-301 | 列表：卡片网格（数据集名、场景徽标、item 总数、草稿数、最新版本号、更新时间）+ 场景筛选 |
| UI-302 | 创建对话框：名称（格式提示）+ 场景单选（5 场景卡片，附示例说明）+ 描述 |
| UI-303 | 详情-数据管理 Tab：草稿区（可编辑/删除）与已发布区（只读）分开展示；item 表格列 = 输入摘要/期望/标签/来源资产 |
| UI-304 | 圈选资产向导：按 filters 检索资产（复用 UI-201 筛选器）→ 勾选 → 预览映射结果（显示 mapped/unmapped 计数与失败原因）→ 确认转入草稿 |
| UI-305 | 发布流程：点「发布新版本」→ 显示变更摘要（新增 N / carried N / 将剔除的非法草稿及原因）→ 输入 changelog → 确认；成功后 toast 并跳到版本时间线 |
| UI-306 | 详情-版本 Tab：垂直时间线（vN、item_count、changelog、发布时间）；每版本操作 = 预览快照（前 50 条表格）/ 导出（JSONL/YAML/HF 下载按钮 + 复制拉取地址）/ 用此版本发起评测（直达评测向导并预选） |
| UI-307 | 详情-badcase Tab：来源为 badcase_feedback 的资产列表（含 run_id 反链到 Run 详情），支持勾选转入草稿 |

### 4.4 评测中心（UI-400）

| 编号 | 需求 |
|---|---|
| UI-401 | Run 列表：表格（状态徽标 running/done/failed、数据集@版本、Target、指标组合、agent_version、通过率色条、weighted_total、发起时间）；筛选 = 状态/数据集/Target；**行内 running 状态自动轮询刷新（3s），done 即停** |
| UI-402 | 发起评测向导（步骤条 4 步）：①选数据集版本（数据集下拉 → 版本下拉，默认最新）②选 Target（列表卡片，显示 kind 与 endpoint）③选指标组合（显示含哪些指标与权重）④确认摘要 → 提交并跳转 Run 详情 |
| UI-403 | Run 详情-概览：顶部指标卡 = total/passed/pass_rate（大号环形图）/weighted_total；指标分布条形图（每指标 avg + n，N/A 灰色标注）；失败分布（按 tag 聚合） |
| UI-404 | Run 详情-逐 case：表格列 = item 输入摘要 / Agent 输出（截断+展开） / 每指标分数（红绿点 + 分值，hover 显示 detail）/ passed 徽标 / error；工具栏 = 仅看失败、按指标筛选、搜索；行点击展开完整输入/输出/轨迹 JSON |
| UI-405 | Run 详情-对比：选择另一个同版本 Run → 上方指标差值表（涨绿↑ 跌红↓）；下方「回归 case」与「修复 case」两个列表（默认展开回归项的对比侧输出）；一键「回灌全部回归 case」 |
| UI-406 | 失败回灌动作：Run 详情任意位置（逐 case 勾选 / 失败筛选栏 / 对比页）均可触发「回灌」对话框：可选附带 tags、可选目标数据集（默认不转入），完成后显示回灌结果（created/skipped/added）与跳转链接 |
| UI-407 | 指标与目标管理页：Target 列表（名称/kind/endpoint 状态点/创建时间）+ 新建表单；MetricConfig 列表（名称/场景/指标 chips 含权重）+ 新建表单（指标动态行：类型下拉 → 按类型渲染参数表单 → 权重/阈值）；指标目录只读表格（来自 GET /metrics，含 description） |

### 4.5 设置（UI-500）

| 编号 | 需求 |
|---|---|
| UI-501 | 只读展示服务端配置状态：鉴权是否开启、LLM Judge 是否已配置（base_url/model，密钥打码）、数据目录路径 |
| UI-502 | SDK/CLI 接入片段生成：当前 API Key（打码可复制）+ pull/CLI 示例代码一键复制 |

## 5. 后端补充需求（UI 依赖，已全部交付 ✅）

| 编号 | 端点 | 说明 | 状态 |
|---|---|---|---|
| FR-B1 | `GET /api/v1/runs?status=&dataset=&target=&offset=&limit=` | Run 摘要列表（含 dataset@version / target / metric_config 名称与 pass_rate / weighted_total，不含 results）；dataset/target 均支持 id 或 name；已删数据集降级显示「(已删除)@N」 | ✅ |
| FR-B2 | `GET /api/v1/stats` | counts（assets/datasets/dataset_versions/runs）、trend_30d（按日 pass_rate 均值+run 数）、draft_datasets（有草稿未发布）、unfeedback_runs（有失败未回灌） | ✅ |
| FR-B3 | Run summary.`failed_tags` | finalize 时聚合失败项 tag 分布（降序前 20），全过 run 不含该键 | ✅ |
| FR-B4 | CORS | `AGENTHUB_CORS_ORIGINS`（逗号分隔，默认 `*`）控制来源白名单 | ✅ |
| FR-B5 | SSE/轮询 | 托管执行进度：优先简单轮询（UI-401 已约定 3s 轮询），后续可升级 SSE | 暂缓 |

> 时区约定：所有时间戳以 UTC 存储（server_default func.now() 与 finished_at 一致），前端负责本地化显示与按天聚合。

## 6. 视觉规范

- **技术选型建议**：Vite + React 18 + TypeScript + Ant Design 5（ProTable/ProForm）+ ECharts 5；构建产物由 FastAPI 静态托管（单服务部署）。
- **色彩**：主色 `#1677ff`（AntD 默认蓝）；语义色——通过 `#52c41a` / 警告 `#faad14` / 失败 `#ff4d4f` / N/A 与禁用 `#bfbfbf`；图表分类色沿用 AntD 色板。
- **布局**：侧边栏 220px（可折叠 64px）；内容区最大宽 1440px 居中；表格密度默认中等，提供紧凑切换。
- **字体**：界面 PingFang SC / Microsoft YaHei；数字（分数）用等宽 tabular-nums。
- **状态徽标全局统一**：running=蓝点脉冲、done=绿、failed=红、draft=灰、published=蓝。
- **分数呈现约定**：0~1 分数一律 ×100 显示为百分比；≥80% 绿 / 50~80% 黄 / <50% 红；N/A 显示「—」灰色并配 tooltip「无法评估」。
- **空状态**：每页配插画 + 主行动按钮（如资产空页「上传第一批数据」）。

## 7. 非功能需求

| 编号 | 需求 |
|---|---|
| UI-N1 | 响应式：≥1280px 完整体验；768~1280 侧边栏折叠；<768 保证列表与详情可读（不承诺完整编辑能力） |
| UI-N2 | 性能：列表页首屏 < 1s（本地）；长表格虚拟滚动（item > 500 条时）；轮询在页面不可见时暂停 |
| UI-N3 | 健壮性：所有请求统一错误 toast（展示服务端 error.message）；401 引导到设置页；请求失败表格保留数据并显示重试 |
| UI-N4 | 无命令行依赖：00-需求文档中的 FR-601 全部 CLI 能力在 UI 均有对应入口（CLI 保留为自动化场景使用） |

## 8. 里程碑建议

| 阶段 | 范围 | 交付 |
|---|---|---|
| UI-M1 | 框架 + 仪表盘 + 资产模块（UI-1xx、UI-2xx、FR-B2） | 可看数据、可导入 |
| UI-M2 | 数据集模块（UI-3xx：圈选/发布/导出） | 数据集生产全程 UI 化 |
| UI-M3 | 评测中心（UI-4xx + FR-B1/B3） | 发起评测、看结果、对比 |
| UI-M4 | 闭环体验打磨（回灌动作贯通、空态引导、设置页） | 全闭环无 CLI |

## 9. 验收标准

1. 用户提供一个 JSONL 文件，不打开终端，可在浏览器完成：导入 → 建集圈选 → 发布 v1 → 发起评测（external Target 回传模式亦可演示）→ 查看通过率与失败明细 → 一键回灌失败 case → 再次圈选发布 v2。
2. Run 对比页能明确指出哪些 case 回归（红）、哪些修复（绿），并能从回归 case 一键回灌。
3. 全站中文、无 404 死链、删除类操作均有确认；74 个后端测试与 UI 并存回归通过。
