# 01 项目概述：AgentHub — 面向 Agent 评测的轻量数据中枢

## 1. 项目定位

**AgentHub** 是一套为个人/小团队 Agent 研发服务的轻量数据中枢，围绕一条核心闭环：

```
统一管理数据资产 → 标准化生产评测数据集 → 以接口/文件形式供给 Agent 项目
→ 采集评测结果 → 沉淀 badcase 反哺数据资产（闭环）
```

它**不是**企业级数据中台，**不是**全功能 LLM 可观测平台，而是一个只解决「评测数据从哪来、怎么管、怎么用、结果怎么沉淀」四个问题的工具。

## 2. 要解决的问题

| 痛点 | 现状 | AgentHub 方案 |
|---|---|---|
| 评测数据散落 | Excel、零散 JSONL、聊天记录里到处都是 | 统一数据资产库，集中上传/采集/去重 |
| 数据集无标准 | 每个 Agent 项目自己定义格式，无法复用 | 统一 Item Schema + 版本化数据集，一次生产多处消费 |
| 供给方式随意 | 手工拷文件、改代码内嵌 | API / SDK / 文件导出（JSONL / YAML / HF 格式）三种供给方式 |
| 结果没有沉淀 | 跑完评测只留一个终端截图 | EvalRun 全量落库，版本间可对比、可回归 |
| badcase 流失 | 发现问题案例后无处安放 | 失败案例一键回灌数据资产，进入下一轮数据集生产 |

## 3. 目标与非目标

### 目标（In Scope）

1. **数据资产管理**：原始对话、Trace、工具调用日志、文档语料的上传、导入（JSONL/CSV/开放 trace 格式）、打标签、去重。
2. **评测数据集生产**：从资产圈选 → 编辑 → 按场景 Schema（单轮 QA / RAG / 工具调用 / 多轮对话 / Agent 轨迹）标准化 → 版本化发布（不可变快照）。
3. **数据供给**：REST API + Python SDK + 文件导出三种方式供 Agent 项目拉取数据集。
4. **评测执行与指标计算**：内置规则指标（精确匹配/包含/JSON Schema 校验等）、LLM Judge 指标、RAG 指标、Agent 轨迹指标；支持本地 Runner 直跑，也支持外部系统回传结果。
5. **结果沉淀与闭环**：Run/Result 落库、数据集版本 × Agent 版本的分数矩阵、回归对比、失败案例回灌。

### 非目标（Out of Scope，明确砍掉）

- ❌ 多租户、组织/团队/角色权限体系（单用户 + 一个 API Key 即可）
- ❌ 全链路数据血缘、字段级血缘图谱
- ❌ 大数据集群依赖（无 Spark / ClickHouse / Kafka，单文件 SQLite 起步）
- ❌ 在线标注平台、多人协同审核工作流（只保留一个极简「待复核」标记）
- ❌ Prompt 管理、Playground、成本核算等 LLM 平台功能（可后续插件化）
- ❌ 分布式部署、高可用、水平扩展

## 4. 核心用户故事

1. **作为 Agent 开发者**，我把线上 agent 的对话 trace 上传到 AgentHub，圈选其中 200 条「查订单失败」的案例，一键生成 `order-agent-regression@v3` 数据集，我的 Agent 项目通过 `agenthub.pull("order-agent-regression@v3")` 拿到标准数据。
2. **作为评测负责人**，我配置指标组合（成功率 + 工具选择准确率 + 答案忠实度），对两个 Agent 版本跑同一数据集，在一张对比表里看到每个指标的涨跌，并定位到具体回归的 case。
3. **作为数据生产者**，我看到 17 个失败 case，把它们标记为「待复核」，复核后直接生成新版本数据集 `@v4`，完成闭环。

## 5. 里程碑规划

| 阶段 | 内容 | 交付物 |
|---|---|---|
| M1 骨架 ✅ | FastAPI 工程脚手架、SQLite 模型、资产上传/列表 | 可运行的 API 服务 |
| M2 数据集 ✅ | 圈选/编辑/Schema 校验/版本发布/文件导出 | 数据集生产可用 |
| M3 供给 ✅ | Python SDK、拉取 API、YAML/JSONL/HF 导出 | Agent 项目可接入 |
| M4 评测 ✅ | Runner、规则指标、LLM Judge、结果落库 | 可跑完整评测 |
| M5 闭环 ✅ | 版本对比、回归检测、badcase 回灌、CLI | 闭环完整可演示 |

全部里程碑已完成：74 个自动化测试通过，CLI 全链路（import → dataset → publish → pull → eval → feedback → compare）真实服务冒烟通过。
