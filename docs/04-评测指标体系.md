# 04 评测指标体系

面向 Agent 评测的四类指标。每类指标是 `agenthub/metrics/` 下的一个插件，实现统一接口：

```python
class Metric(Protocol):
    name: str                      # 如 "llm_judge", "tool_accuracy"
    def evaluate(self, item: DatasetItem, output: AgentOutput) -> MetricScore: ...
    # MetricScore = {"score": float|bool, "detail": str, "cost": {...}}
```

## 1. 规则类（rule:*，零成本、确定性）

| 指标 | 判定逻辑 | 适用场景 |
|---|---|---|
| `rule:exact` | 严格相等（可配置忽略大小写/空白） | QA 有标准短答案 |
| `rule:contains` / `rule:not_contains` | 子串包含 | 关键事实校验 |
| `rule:regex` | 正则匹配 | 格式类（订单号、日期） |
| `rule:json_schema` | 输出是否符合 JSON Schema | 结构化输出 |
| `rule:one_of` | 命中枚举集合 | 意图分类 |
| `rule:numeric_within` | 数值误差容忍（±ε 或 ±%） | 计算/统计类 |

## 2. 语义类（LLM Judge，借鉴 DeepEval G-Eval）

用 LLM 按评分细则打 0~1 分，返回分数 + 理由：

| 指标 | 衡量 | Prompt 要点 |
|---|---|---|
| `judge:correctness` | 答案与标准答案的事实一致性 | 给 ground truth，要求分档：完全正确=1 / 主体正确=0.7 / 部分=0.4 / 错误幻觉=0 |
| `judge:faithfulness` | 回答是否忠于 context（防幻觉） | 只给 context 与回答，不给标准答案 |
| `judge:completeness` | 是否回答了问题的所有部分 | 列出问题拆解后逐项核对 |
| `judge:safety` | 是否触发安全红线 | 红线清单 + 0/1 判定 |
| `judge:custom` | 用户自定义 rubric | MetricConfig 中内联 rubric 文本 |

实现要点：温度 0、JSON 输出校验（复用 `rule:json_schema` 的解析）、失败重试 2 次后记 N/A 不阻塞整批。

## 3. RAG 类（借鉴 RAGAS，可选用 RAGAS 实现或内置轻量版）

| 指标 | 公式/方法 | 需要字段 |
|---|---|---|
| `rag:context_precision` | 相关 context 是否排在前面 | question, ground_truth, contexts |
| `rag:context_recall` | 标准答案的信息被 context 覆盖的比例 | 同上 |
| `rag:answer_relevancy` | 回答与问题的相关度（生成反问句余弦，或 LLM 打分） | question, answer |
| `rag:faithfulness` | 回答中可归因到 context 的陈述占比 | answer, contexts |

## 4. Agent 轨迹类（trajectory:*，借鉴 GAIA/AgentBench 加权维度）

针对 `trajectory` 场景，从 Agent 上报的 `trajectory`（steps: 思考/工具调用/观察序列）计算：

| 指标 | 定义 |
|---|---|
| `traj:outcome_success` | 最终 outcome 是否达成（通常接 `rule:exact` 或 `judge:correctness`） |
| `traj:tool_selection` | 实际调用的工具集合 vs `must_call_tools`/`must_not_call_tools` 约束的命中度 |
| `traj:tool_args_accuracy` | 关键工具的参数与 expected.args 的一致性（逐字段比对） |
| `traj:step_efficiency` | 实际步数 / 理论最少步数（`1 - (steps-min)/(max-min)` 归一） |
| `traj:redundant_call_rate` | 重复/无效工具调用占比 |
| `traj:latency` / `traj:token_cost` | 端到端时延与 token 消耗（记录型指标，不算 pass/fail） |

## 5. Run 聚合与对比

- **聚合分**：每个指标输出 `avg(score)` 与 `pass_rate`；支持在 MetricConfig 里配置加权总分（如 GAIA 式：correctness 25% + tool 20% + efficiency 10%…）。
- **对比**（`GET /runs/compare`）输出三层：
  1. 指标级：两 Run 各指标分值与差值（含加权总分）
  2. Case 级：`passed 翻转` 的 Item 列表（新过/新败）
  3. 明细级：单 Item 两个 Run 的 output/trajectory 并排

## 6. 推荐的默认指标组合（MetricConfig 预置）

| 配置名 | 场景 | 组成 |
|---|---|---|
| `qa-basic` | qa | rule:exact + judge:correctness |
| `rag-standard` | rag | judge:faithfulness + rag:context_recall + rag:answer_relevancy |
| `tool-accuracy` | tool_call | traj:tool_selection + traj:tool_args_accuracy |
| `agent-e2e` | trajectory | traj:outcome_success(50%) + traj:tool_selection(25%) + traj:step_efficiency(15%) + traj:token_cost(10%, 记录) |
