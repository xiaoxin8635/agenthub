# 04 评测指标体系

面向 Agent 评测的指标插件体系（as-built）。每个指标是 `agenthub/metrics/` 下带 `@register` 的插件类，实现统一接口：

```python
class Metric(Protocol):
    name: str                                   # 类型标识，如 "rule:exact"、"traj:tools_called"
    def evaluate(self, item: dict, output: dict, spec: dict) -> MetricScore: ...
    # MetricScore = {"score": 0.0~1.0|None, "detail": str, "passed": bool|None}
    # score=None 表示 N/A（无法评估），不参与通过判定与加权总分
```

指标规格存储在 MetricConfig.metrics 中，形如 `{"type": "rule:exact", "actual": "answer", "expected_path": "expected.answer", "weight": 1}`。公共 spec 参数：`actual`（从 output 取值的点路径，默认 "answer"）、`expected_path`/`value`（期望值来源）、`threshold`（通过阈值）、`weight`（聚合权重）。

当前注册表（17 个）：

| 前缀 | 类别 | 状态 |
|---|---|---|
| `rule:*` | 纯函数、确定性、零成本 | 已实现 8 个 |
| `judge:*` | LLM 评分（OpenAI 兼容接口，需 `AGENTHUB_LLM_*` 配置） | 已实现 6 个 |
| `traj:*` | Agent 轨迹规则评估 | 已实现 3 个 |
| `rag:*` | RAG 专用指标 | 预留前缀，未实现（RAG 评估由 `judge:context_*` 覆盖） |

## 1. 规则类（rule:*，零成本、确定性）

| 指标 | 判定逻辑 | 适用场景 |
|---|---|---|
| `rule:exact` | 严格相等（可配置忽略大小写） | QA 有标准短答案 |
| `rule:contains` / `rule:not_contains` | 子串包含 | 关键事实校验 |
| `rule:regex` | 正则匹配 | 格式类（订单号、日期） |
| `rule:json_schema` | 输出是否符合 JSON Schema | 结构化输出 |
| `rule:one_of` | 命中枚举集合 | 意图分类 |
| `rule:numeric_within` | 数值误差容忍（绝对/相对容差） | 计算/统计类 |
| `rule:custom` | 按 kind 分派：contains_any / length_range / regex / numeric_within / json_schema | 前端友好的一站式自定义规则 |

## 2. 语义类（judge:*，LLM Judge，借鉴 DeepEval G-Eval）

用 LLM 按评分细则打 0~1 分，返回分数 + 理由（温度 0、JSON 输出、失败重试 2 次；测试环境自动隔离，judge 指标记 N/A）：

| 指标 | 衡量 | Prompt 要点 |
|---|---|---|
| `judge:correctness` | 答案与标准答案的事实一致性 | 给 ground truth，分档：完全正确=1 / 主体正确=0.7 / 部分=0.4 / 错误幻觉=0 |
| `judge:faithfulness` | 回答是否忠于参考资料（防幻觉） | 只给 context 与回答，不给标准答案；`context_source: "output"` 时用被测系统回填的真实 citations |
| `judge:context_recall` | 标准答案的信息被检索切片覆盖的程度 | RAGAS 风格，只评检索素材不评回答 |
| `judge:context_precision` | 检索切片与问题的相关占比 | precision@k 简化版，只评切片本身 |
| `judge:trajectory` | Agent 执行轨迹：工具选择/路径效率/结果达成 | 见第 4 节 |
| `judge:custom` | 用户自定义 rubric | spec.rubric 内联评分细则 |

规划中未实现：`judge:completeness`（回答完整度）、`judge:safety`（安全红线）。

## 3. RAG 类（由 judge:context_* 覆盖）

`rag:*` 前缀为分类预留，当前未单独实现；RAG 评估能力由语义类的 RAGAS 风格指标提供：

- 检索质量：`judge:context_recall` + `judge:context_precision`
- 生成质量：`judge:faithfulness`（防幻觉）+ `judge:correctness`
- 端到端 RAG 评测的前提：被测系统把真实检索到的切片回填到 `output.context.citations`（`context_source: "output"`），否则只能基于评测集给定 passages 评生成质量，检索环节不可见。

规划中未实现：`rag:answer_relevancy`（生成反问句余弦）。

## 4. Agent 轨迹类（traj:*，借鉴 GAIA/AgentBench 维度）

针对 `trajectory` 场景。轨迹数据经 `agenthub/metrics/traj_parse.py` 宽松归一化后评估——兼容 `{"steps": [...]}` 包装、直接列表、键别名（tool/tool_name/name/action/function；args/arguments/input/parameters/params），形状不符的步骤跳过；**未解析到工具调用时统一记 N/A**，确定性约束由 `traj:tools_called` 负责。

| 指标 | 定义 | spec 要点 |
|---|---|---|
| `traj:tools_called` | 调用序列满足 `must_call_tools` / `must_not_call_tools` 约束；禁用工具命中直接 0 分；`partial: true` 按 must_call 命中比例给分 | 默认读 item.expected 对应字段，spec 可覆盖 |
| `traj:max_steps` | 工具调用次数 ≤ 上限（效率约束，超限记 0） | 默认取 `context.max_steps`，spec.max_steps 可覆盖 |
| `traj:tool_args` | 指定工具的全部调用参数做 JSON Schema 校验 | 需 spec.tool + spec.schema；未调用该工具记 N/A |
| `judge:trajectory` | LLM 评审轨迹：工具选择合理性/路径效率/结果达成（默认 rubric，spec.rubric 可覆盖） | task/expected 路径可覆盖；无轨迹记 N/A |

规划中未实现：`traj:redundant_call_rate`（重复调用占比）、`traj:latency` / `traj:token_cost`（记录型指标，需 Runner 采集时延与 token 数据）。

## 4.5 multi_turn 逐轮评估（spec.turn_scope）

指标 spec 的可选字段 `turn_scope`（在 `eval_service.evaluate_item` 统一分派，托管/回传两种模式自动生效；前端指标组合表单在 multi_turn 场景下显示选择器）：

| turn_scope | 行为 |
|---|---|
| 未设置（默认） | 整 output 评估，与历史行为完全一致 |
| `last` | 构造 qa 形状子 item（`input.question`=最后一轮 user 消息、`expected.final_answer` 提升为 `expected.answer`）后评估——`judge:correctness` 等有默认路径的指标零配置可用；rule 类指标仍需显式 `expected_path` |
| `each` | output 逐轮回答切片（宽松解析 `turn_answers`/`answers`/`turns`/`messages`/`history`，元素支持字符串或 `{"content": ...}`），每轮独立评估；score=可评轮均值，passed=全部可判轮通过；输出无逐轮回答结构时记 N/A（不静默回退） |

`each` 模式注意事项：每轮 sub_item 注入该轮问题（`question_path` 默认路径逐轮命中）；`expected` 不做映射（multi_turn 只有 `final_answer`，前几轮拿它当标准答案是错误行为）——需要期望值的指标在 each 模式下仅对最后一轮有意义，逐轮质量评估建议配合 `judge:custom`、`rule:custom` 等无期望值指标。归一化与包装实现在 `agenthub/metrics/turn_eval.py`。

## 5. Run 聚合与对比

- **聚合分**：每个指标输出 `avg(score)` 与 `pass_rate`；MetricConfig 里配置 `weight` 得加权总分 `weighted_total`（score 为 N/A 的指标不进入加权分母）。
- **对比**（`GET /runs/compare`）输出三层：
  1. 指标级：两 Run 各指标分值与差值（含加权总分）
  2. Case 级：`passed 翻转` 的 Item 列表（新过/新败）
  3. 明细级：单 Item 两个 Run 的 output/trajectory 并排

## 6. 推荐的默认指标组合（MetricConfig 预置）

| 配置名 | 场景 | 组成 |
|---|---|---|
| `qa-basic` | qa | rule:exact + judge:correctness |
| `rag-standard` | rag | judge:faithfulness + judge:context_recall + judge:context_precision |
| `tool-accuracy` | tool_call | rule:exact(actual=tool) + rule:json_schema(actual=args 对应路径) |
| `agent-e2e` | trajectory | traj:tools_called(30%) + traj:max_steps(15%) + traj:tool_args(25%) + judge:trajectory(30%) |
