# 00 需求文档：AgentHub

> 本文档是 AgentHub 的**需求基线（as-built）**：记录系统应该做什么、每条需求如何验收。项目定位、痛点分析、目标/非目标的完整论述见 [01-项目概述](./01-项目概述.md)；技术实现见 [02-架构设计](./02-架构设计.md) 与 [03-数据模型与API设计](./03-数据模型与API设计.md)。

## 1. 需求总览

围绕核心闭环「**资产管理 → 数据集生产 → 数据供给 → 评测执行 → 结果沉淀与回灌**」，功能需求按六个模块编号：

| 模块 | 需求段 | 一句话职责 |
|---|---|---|
| 数据资产管理 | FR-1xx | 原始语料的归集、去重、打标、检索 |
| 评测数据集生产 | FR-2xx | 资产圈选 → 场景标准化 → 版本化发布 |
| 数据供给 | FR-3xx | API / SDK / 文件三种方式供 Agent 拉取 |
| 评测执行与指标 | FR-4xx | 双模式评测 + 可插拔指标 + 聚合落库 |
| 结果沉淀与闭环 | FR-5xx | Run 对比、回归检测、badcase 回灌 |
| CLI 与通用能力 | FR-6xx | 命令行全链路操作、鉴权、统一响应 |

## 2. 用户与核心场景

系统为**单用户/小团队**设计（一个 API Key 即可使用），三类角色其实是同一个人的三顶帽子：

| 角色 | 核心场景 | 涉及需求 |
|---|---|---|
| Agent 开发者 | 上传线上 trace → 圈选失败案例 → 生成回归集 → Agent 项目 `pull` | FR-1xx, FR-2xx, FR-3xx |
| 评测负责人 | 配置指标组合 → 对两个版本跑同一数据集 → 看指标涨跌与回归 case | FR-4xx, FR-5xx |
| 数据生产者 | 复核失败 case → 回灌资产 → 产出新版本数据集 | FR-1xx, FR-2xx, FR-5xx |

## 3. 功能需求

### 3.1 数据资产管理（FR-1xx）

| 编号 | 需求 | 验收标准 | 状态 |
|---|---|---|---|
| FR-101 | 资产类型与来源受控 | type ∈ {dialog, trace, tool_log, doc, custom}；source ∈ {manual, trace_import, badcase_feedback}；越界返回 422 | ✅ |
| FR-102 | 单条创建与内容级去重 | `POST /assets`；同 content（canonical JSON sha256）重复返回 409 | ✅ |
| FR-103 | JSONL 批量导入 | `POST /assets/import`（multipart，Form 参数 source/tags 逗号分隔）；逐行容错，坏行计入 errors 不中断；content_hash 幂等（重复跳过） | ✅ |
| FR-104 | 资产列表与检索 | `GET /assets` 支持 type/source/tag/q（中文 LIKE）过滤 + offset/limit 分页，返回 total | ✅ |
| FR-105 | 资产标签维护 | `PATCH /assets/{id}` 可更新 tags/meta（content 不可变，保证去重可靠）；`DELETE /assets/{id}` 删除 | ✅ |
| FR-106 | 资产结构 | Asset = {type, source, content(任意 JSON dict), tags, meta, content_hash, created_at}，content 不做 schema 限制 | ✅ |

### 3.2 评测数据集生产（FR-2xx）

| 编号 | 需求 | 验收标准 | 状态 |
|---|---|---|---|
| FR-201 | 数据集创建 | name 唯一（409）、scene ∈ 5 场景注册表（422）、可附 description | ✅ |
| FR-202 | 五场景 Item Schema 强校验 | qa / rag / tool_call / multi_turn / trajectory 各有 payload 校验规则，非法 item 明确报错 | ✅ |
| FR-203 | 草稿编辑模型 | item 先入草稿（dataset_id 归属）；支持直接添加、从资产圈选（asset_ids 或 filters，结构化 content 直通 + 场景启发式映射）；同名 source_asset_id 去重；草稿可删除 | ✅ |
| FR-204 | 版本化发布 | `POST /datasets/{id}/versions`：草稿 + 历史 carried = 新版本；发布后**不可变**；无草稿且无历史返回 422；非法草稿按 skip_invalid 剔除并统计 | ✅ |
| FR-205 | 不可变快照落盘 | 每版本快照 JSONL 写入 `data/snapshots/{name}/v{N}.jsonl`，作为供给真相源；stats 记录 carried/new/tags 分布 | ✅ |
| FR-206 | 数据集删除 | 级联删除草稿 items；已发布版本快照文件保留（人工清理） | ✅ |
| FR-207 | 数据集定位双通道 | API 路径中的 {dataset_id} 同时接受 id 或 name | ✅ |

### 3.3 数据供给（FR-3xx）

| 编号 | 需求 | 验收标准 | 状态 |
|---|---|---|---|
| FR-301 | 解析端点 | `GET /supply/datasets/{name}/resolve` 返回 latest_version / scene / item_count；无已发布版本 404 | ✅ |
| FR-302 | 最新版直链 | `GET /supply/datasets/{name}/latest` 302 重定向到当版本 JSONL 导出 | ✅ |
| FR-303 | 文件导出 | `GET /datasets/{name}/versions/{N}/export?format=`：jsonl（原生）/ yaml（promptfoo 兼容：vars/assert/metadata 无损）/ hf（`splits.train`）；非法 format 422 | ✅ |
| FR-304 | Python SDK | `AgentHub(base_url, api_key, cache_dir).pull("name[@N]")`；显式版本 + 缓存命中 = **零网络请求**（版本不可变保证）；返回 Item/Dataset dataclass | ✅ |
| FR-305 | SDK 引用语法 | `name`（自动解析最新）与 `name@N`（显式版本）；非法 ref 明确报错 | ✅ |

### 3.4 评测执行与指标（FR-4xx）

| 编号 | 需求 | 验收标准 | 状态 |
|---|---|---|---|
| FR-401 | 被测目标管理 | EvalTarget：kind ∈ {http(托管), external(仅回传)}；http 必须带 endpoint_config.url | ✅ |
| FR-402 | 指标组合管理 | MetricConfig：scene + 指标列表（type/weight/threshold/自有参数）；未知指标类型创建时 422 | ✅ |
| FR-403 | 指标可插拔 | 注册表机制，10 个内置指标：rule:exact / contains / not_contains / regex / json_schema / one_of / numeric_within + judge:correctness / faithfulness / custom；`GET /api/v1/metrics` 列出全部（type/kind/description） | ✅ |
| FR-404 | 指标统一接口 | `Metric.evaluate(item, output, spec) -> MetricScore(score 0~1 / detail / passed)`；score=None 表示 N/A | ✅ |
| FR-405 | 托管执行（http Runner） | `POST /runs/{id}/start` 后台线程逐条调 Agent HTTP（标准协议 `{"output":..., "trajectory":...}`）；Agent 调用失败记为该条 error，不导致 Run 失败；完成后自动聚合 | ✅ |
| FR-406 | 回传执行（external） | `POST /runs/{id}/results` 幂等（重复 item 跳过）；收齐自动聚合；支持 `POST /finalize` 强制出分 | ✅ |
| FR-407 | 双模式统一算分 | 托管与回传共用 evaluate_item / compute_summary；item 输出不属于该版本 422 | ✅ |
| FR-408 | 聚合与加权总分 | summary = total/passed/pass_rate/逐指标 avg+pass_rate+n/weighted_total（Σscore×weight/Σweight，N/A 不参与分子分母）；全部 N/A 时 weighted_total=null | ✅ |
| FR-409 | 结果查询 | `GET /runs/{id}/results?passed=&offset=&limit=`，可只取失败项 | ✅ |
| FR-410 | LLM Judge 可配置 | OpenAI 兼容接口，经 AGENTHUB_LLM_BASE_URL/API_KEY/MODEL 配置；未配置时 judge:* 返回 N/A 不阻塞 Run | ✅ |

### 3.5 结果沉淀与闭环（FR-5xx）

| 编号 | 需求 | 验收标准 | 状态 |
|---|---|---|---|
| FR-501 | Run 全量落库 | Run/Result 持久化（dataset_version × target × metric_config × agent_version），可回查任意历史 | ✅ |
| FR-502 | 失败 case 回灌 | `POST /runs/{id}/feedback`：失败项 → 资产（source=badcase_feedback，content 含 input/expected/context/agent_output/error/run_id，tags 含 `run:{id}`，meta 含 agent_version/source_item_id）；重复回灌按内容指纹去重 | ✅ |
| FR-503 | 回灌入数据集 | feedback 带 dataset 时，本次涉及的资产（含此前已存在的）转入该数据集草稿并打 `badcase` 标签，返回 added_items | ✅ |
| FR-504 | Run 对比 | `GET /runs/{id}/compare/{other}`：common_items、逐指标 delta、weighted_total delta、regressions（由过转败，附对比侧 output/scores）、fixed（由败转过）、both_passed/both_failed | ✅ |
| FR-505 | 回灌资产可再生产 | badcase 资产 content 为结构化直通格式，可被任意场景数据集经 FR-203 圈选进入下一版数据集 | ✅ |

### 3.6 CLI 与通用能力（FR-6xx）

| 编号 | 需求 | 验收标准 | 状态 |
|---|---|---|---|
| FR-601 | CLI 命令覆盖全链路 | `python -m agenthub.cli`：import / dataset-create / dataset-select / dataset-publish / pull / eval / run-show / compare / feedback / metrics list | ✅ |
| FR-602 | CLI 连接配置 | 全局 --base-url/--api-key，默认取 env `AGENTHUB_URL`（默认 http://localhost:8300）/ `AGENTHUB_API_KEY` | ✅ |
| FR-603 | eval 托管评测 | `eval REF --target N --metrics N [--agent-version] [--wait/--timeout]`：名字解析 → 创建 → 启动 → 轮询至 done/failed，输出 summary | ✅ |
| FR-604 | CLI 错误语义 | 失败输出到 stderr 并返回非 0 退出码；成功输出 JSON（ensure_ascii=False）到 stdout | ✅ |
| FR-605 | 统一响应与鉴权 | 全部响应 `{code, data}` / `{code, error}`；HTTP 错误全局 handler；`X-API-Key` 校验（AGENTHUB_API_KEY 为空 = 开发模式放行） | ✅ |
| FR-606 | 配置环境化 | pydantic-settings，`AGENTHUB_` 前缀：DB_URL / DATA_DIR / API_KEY / LLM_BASE_URL / LLM_API_KEY / LLM_MODEL | ✅ |

## 4. 关键数据与格式规范

1. **评测 Item（快照行）**：`{"id", "input", "expected", "context", "tags", "source_asset_id"}` —— Agent 侧消费的最小契约。
2. **Agent 标准响应协议**（托管模式）：`{"output": {...}, "trajectory": {...}}`；兼容仅含 `answer` 字段或整体字符串。
3. **版本不可变**：已发布版本的数据、快照文件永不修改；「修改数据」的唯一途径是发布新版本。
4. **badcase 资产 content 约定**：`input/expected/context` 三键为结构化直通（保证再生产时任意场景可圈选），`agent_output/error/run_id` 为排查上下文。

## 5. 非功能需求（NFR）

| 编号 | 需求 | 验收标准 | 状态 |
|---|---|---|---|
| NFR-01 | 轻量可运行 | 单机 `uvicorn agenthub.main:app` 即起；SQLite 单文件 + 快照目录，无外部依赖（Redis/Kafka/向量库） | ✅ |
| NFR-02 | 数据安全 | 快照文件即真相源，DB 可随时由快照+资产重建；JSON 序列化 ensure_ascii=False（中文标签/检索可用） | ✅ |
| NFR-03 | 可测试 | 全部需求有自动化测试覆盖（pytest，74 通过），含 live server 端到端与 CLI 全链路 | ✅ |
| NFR-04 | 幂等与容错 | 导入逐行容错；回传幂等；资产内容级去重；Run 失败不丢已算分数据 | ✅ |
| NFR-05 | 中文友好 | 中文 tags/搜索/LLM 评分全链路可用 | ✅ |
| NFR-06 | 事务一致性 | 托管 Runner 整个 Run 单事务提交，不暴露半成品结果 | ✅ |

## 6. 约束与假设

- 单用户假设：不做多租户/角色权限；一个 API Key 即全部凭据。
- 规模假设：单数据集 ≤ 万级 items、资产库 ≤ 十万级，SQLite 足够。
- LLM Judge 依赖外部 OpenAI 兼容服务，未配置时优雅降级（N/A）。
- 生产化演进（已识别、暂不做）：Alembic 迁移、PostgreSQL、多进程部署。
