# 05 参考项目调研（GitHub）

调研目标：找到与「评测数据集管理 + Agent 评测闭环」相似的开源项目，借鉴其模型与实现，同时明确 AgentHub 的差异化定位（做减法）。

## 1. 对比总览

| 项目 | Stars 量级 | 定位 | 数据集管理 | Agent 指标 | 闭环（结果→数据） | 对我们的适用度 |
|---|---|---|---|---|---|---|
| [Langfuse](https://github.com/langfuse/langfuse) | ~15k+ | AI 工程平台（trace+prompt+eval） | ★★★ Datasets+Experiments | ★★ 集成 DeepEval/RAGAS | 部分（trace→dataset 手动） | 架构参考，但太重 |
| [promptfoo](https://github.com/promptfoo/promptfoo) | ~6k+ | LLM 测试框架 | ★★ YAML 声明式 tests | ★★ 断言类型丰富 | ✗（文件即终点） | 数据集格式与断言体系借鉴 |
| [DeepEval](https://github.com/confident-ai/deepeval) | ~5k+ | 评测指标库（pytest 风格） | ★★★ 黄金集+数据集版本 | ★★★ G-Eval 等 14+ 指标 | ✗ | 指标接口设计借鉴 |

## 2. 各项目关键借鉴点

### 2.1 Langfuse —— 闭环形态的参照（但做减法）

Langfuse 的核心回路是 **Trace → Dataset Item → Experiment（Run）→ Score**：

- 它证明了「数据集版本 × 实验」的矩阵式结果管理是好用的；
- 其部署架构（Web + Worker + PostgreSQL + ClickHouse + Redis + S3）正是我们要**避开**的重型方案；
- 借鉴：Run/Summary/逐 Item Score 的三层结果模型、Dataset Item 可从 trace 一键生成；
- 差异：我们砍掉 trace 全量观测与 prompt 管理，把「失败案例回灌」做成自动闭环而非手动导入。

### 2.2 promptfoo —— 数据集文件格式

其 `promptfooconfig.yaml` 的 `vars + assert` 模型：

```yaml
tests:
  - vars: { message: "如何重置密码" }
    assert:
      - type: contains
        value: "重置链接"
      - type: is-json
```

- 借鉴：断言类型体系（contains / is-json / similar / llm-rubric）直接映射为我们的 `rule:*` + `judge:*` 指标；提供 promptfoo YAML 导出，使其存量用户零成本迁移。

### 2.3 DeepEval —— 指标接口

- 每个指标是一个类，`measure()` 返回 score + reason，支持 `threshold` 与 `evaluation_steps`；
- 借鉴：我们 `Metric` Protocol 的 `MetricScore{score, detail}` 结构与此对齐，便于未来直接适配 DeepEval/RAGAS 作为外部指标插件。

### 2.4 RAGAS —— RAG 指标

- faithfulness / context_precision / context_recall / answer_relevancy 四件套已是事实标准；
- 借鉴：`rag:*` 指标定义照搬，实现上「内置轻量版（LLM judge 实现）+ 可选直接调 RAGAS」双轨。

### 2.5 GAIA / AgentBench —— Agent 轨迹指标维度

- GAIA 按正确性/工具选择/上下文保持/完整性/效率做加权评分，分 Level 难度；
- 借鉴：`traj:*` 指标族与加权总分机制（见 [04-评测指标体系.md](./04-评测指标体系.md) 第 4 节）；数据集可加 `difficulty` tag 便于分层统计。

### 2.6 Argilla —— 审核回路

- 标注队列 → 确认 → 入数据集的流程；
- 借鉴：badcase「待复核」标记 + 复核后入数据集的最小流程；砍掉其多人协同、规则引擎等企业功能。

## 3. 差异化定位结论

```
Langfuse = 全功能平台（重）          promptfoo/DeepEval = 本地库（无中央数据资产）
              └──────── AgentHub = 两者之间：中央数据资产 + 轻服务 + 闭环 ────────┘
```

三个没有人同时做到、而我们作为核心特性的点：

1. **badcase 自动回灌**（结果 → 资产 → 新版本数据集的一条命令闭环）；
2. **快照文件即真相**（数据集版本落 JSONL 文件，可 git、可 diff、可被任意脚本直接消费）；
3. **双执行模式**（托管 Runner + 任意语言回传），不锁定 Agent 技术栈。
